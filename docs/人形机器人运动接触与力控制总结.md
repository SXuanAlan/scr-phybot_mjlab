# 人形机器人如何学习运动、接触与力

## 核心观点

让人形机器人完成擦拭、坐靠、抓取和搬运等任务，不能只优化“动作看起来像不像”，而要同时学习：

\[
\boxed{
\text{Motion intent}
+
\text{Contact intent}
+
\text{Force interaction}
+
\text{Object outcome}
+
\text{Closed-loop feedback}
}
\]

- **Motion**：身体应该怎样运动、关键点应该到哪里。
- **Contact**：哪个身体部位应在何时接触或避开哪个物体。
- **Force**：接触后应施加多大、什么方向、持续多久的力。
- **Object outcome**：物体是否真的被擦动、支撑、抬起或搬到目标位置。
- **Feedback**：发生偏差、滑动或掉落后，能否根据真实状态在线修正。

## 为什么只做 motion tracking 不够

关键点误差只描述几何位置，并不证明物理交互成功。手停在白板前 2 cm 与真正压住白板，在关键点指标上可能很接近，但前者没有法向力和摩擦力，无法擦除；手移动到箱子两侧也不等于箱子受到足够夹持力并被抬起。

纯关键点策略甚至可能偏好“靠近但不接触”，因为真实碰撞、摩擦和物体运动会扰乱参考轨迹。于是会出现：

\[
\text{motion looks correct}
\quad\text{but}\quad
\text{physical task fails}.
\]

因此，**keypoint 是动作提示，contact 和 object state 才能证明交互发生，task outcome 才能证明任务完成。**

## 一个完整的学习目标

策略可接收：

\[
a_t=\pi(s_t,k_t,c_t,o_t,f_t^*)
\]

其中：

- \(s_t\)：关节、速度、基座姿态等本体状态；
- \(k_t\)：参考关键点或稀疏身体目标；
- \(c_t\)：期望接触状态；
- \(o_t\)：物体位姿、速度及相对关系；
- \(f_t^*\)：可选的目标接触力或目标 wrench。

对应奖励通常包含：

\[
r_t=
w_m r_{\text{motion}}
+w_c r_{\text{contact}}
+w_o r_{\text{object}}
+w_f r_{\text{force}}
+w_s r_{\text{safety}}.
\]

### 1. Motion reward

跟踪身体位置、方向、关节姿态与速度，保证动作风格、平衡和全身协调。

### 2. Contact reward

比较期望接触与仿真实际接触：

- 该碰的部位必须真正接触；
- 不该碰的部位应避免碰撞；
- 用距离奖励缓解二值接触信号过于稀疏的问题。

### 3. Object reward

直接检查物体的位置、方向和运动结果。如果手的轨迹正确但箱子没抬起，物体奖励仍然很低，从而堵住“动作对、物体不动”的漏洞。

### 4. Force reward

“学会力”有两种含义：

- **隐式力学习**：不指定精确力值，只根据接触和任务结果，学习产生足以完成任务的力。
- **显式力学习**：给出目标力 \(f_t^*\) 或安全区间 \([f_{\min},f_{\max}]\)，直接惩罚力不足、过大或冲击峰值。

精确擦拭压力、易碎物抓取和双臂载荷分配通常需要显式力目标、力反馈，以及阻抗控制或力—位置混合控制。

## 如何确保策略真的使用 contact command

只添加 contact label 和奖励仍可能不够。若训练数据中“手靠近表面”总与“contact = 1”同时出现，策略可以从关键点直接猜出接触状态，完全忽略 contact 输入。

解决方法是加入反事实样本：

| 相似的关键点条件 | 接触要求 |
|---|---|
| 手靠近物体 | 接触 |
| 手靠近物体 | 不接触 |
| 手略微远离物体 | 主动修正并接触 |
| 手略微远离物体 | 保持不接触 |

只有当相似 motion 对应不同 contact，策略才必须把 contact 当作独立、可控的命令。若还希望力可控，也应在相似姿态下提供不同目标力。

## ContactMimic 与 OmniContact

| 维度 | ContactMimic | OmniContact |
|---|---|---|
| 核心问题 | 接触能否与关键点解耦并独立开关 | 接触表示能否支持统一技能、规划与长时序执行 |
| 控制输入 | 参考关键点 + 当前身体部位接触标签 | 稀疏未来身体目标 + 未来接触序列（Contact Flow） |
| 接触范围 | 覆盖手腕、肩、躯干、骨盆、腿等多种身体部位 | 主要关注双手和双脚末端 |
| 物体反馈 | actor 不依赖实时物体位姿 | 观察物体相对 6D 位姿、包围盒与历史状态 |
| 物体目标 | 主要优化 motion 与 contact，物体运动可作为涌现结果 | 显式优化物体位置、方向及手—物相对关系 |
| 关键设计 | 反事实数据增强，防止策略忽略 contact command | CF-Gen 高层规划 + CF-Track 统一执行 |
| 在线恢复 | 无显式物体级重新规划 | 可根据物体偏差重新生成 Contact Flow |
| 适用重点 | 接触 on/off、全身接触、接触可辨识性 | 搬运、推动、堆叠、技能组合与失败恢复 |

### ContactMimic

ContactMimic 重点回答：

> 固定相同或相似的关键点轨迹，仅改变 contact command，机器人能否产生“接触”和“不接触”两种不同物理行为？

它通过 contact-label flipping、object removal 和 inflated geometry 等增强，构造“相似 motion、不同 contact”的样本。其突出贡献是证明 contact command 没有被关键点捷径取代，并能控制坐/蹲、靠/不靠、擦拭/悬停等全身接触行为。

局限在于：它主要执行预先给定的参考动作，不显式观察物体实时位姿，也不负责长时序规划或掉落后的重新抓取。它主要学习“是否建立有效接触”，而不是精确跟踪指定的力—时间曲线。

### OmniContact

OmniContact 重点回答：

> 能否把未来身体目标与接触时序组成统一的 Contact Flow，并用它生成、执行和串联多种操作技能？

它直接观察和优化物体状态，因此当手部动作正确但箱子没有跟上时，object 和 interaction rewards 会暴露失败。高层 CF-Gen 根据任务生成 Contact Flow，低层 CF-Track 负责稳定执行；当物体偏离计划时，还可在线重新规划。

它更接近完整的 loco-manipulation 系统，但对“固定完全相同的关键点后独立切换接触”这一反事实问题，没有 ContactMimic 那样专门和严格。

一句话概括：

\[
\boxed{
\text{ContactMimic 深挖“接触是否可独立控制”，}
\quad
\text{OmniContact 扩展“接触如何成为规划—控制接口”。}
}
\]

## 实用训练流程

1. **运动基础**：先学习站立、平衡、行走和全身 motion tracking。
2. **接触学习**：加入接触标签、距离 shaping、接触匹配、错误碰撞惩罚和反事实数据。
3. **物体作用**：观察并奖励物体位置、方向、手—物关系以及抬起、推动、放置等结果。
4. **力调节**：加入目标力或安全区间、滑动与冲击惩罚，并采用柔顺控制接口。
5. **鲁棒性与恢复**：随机化质量、摩擦、尺寸和动力学参数，主动制造漏抓、滑落和外力扰动，让策略学会修正与重新抓取。

## 评价指标

不能只报告 MPJPE，还应同时评价：

| 层面 | 典型指标 |
|---|---|
| Motion | MPJPE、姿态误差、动作自然度 |
| Contact | precision/recall、接触持续时间、错误碰撞率 |
| Force | 力误差、接触冲量、峰值冲击 |
| Object | 位置与方向误差、物体位移、滑动率 |
| Task | 抓取、搬运、放置或擦拭成功率 |
| Robustness | 不同质量、摩擦和扰动下的成功率 |

## 最终总结

要从“动作模仿”走向“物理交互”，机器人必须依次学会：

\[
\boxed{
\begin{aligned}
\text{Motion} &: \text{身体怎样运动} \\
\text{Contact} &: \text{何时、何处、用哪个部位接触} \\
\text{Force} &: \text{接触后如何施力与分配载荷} \\
\text{Outcome} &: \text{物体是否真的按目标运动} \\
\text{Feedback} &: \text{偏差或失败后如何在线修正}
\end{aligned}
}
\]

ContactMimic 主要补上了从 motion 到可控 contact 的一层；OmniContact 进一步连接 contact、object outcome 和在线 replanning。若任务要求精确力控制，还需加入目标力表示、真实或估计的力反馈，以及柔顺的底层控制。
