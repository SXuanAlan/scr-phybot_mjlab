**单 unit：根据真仿残差辨识，并在辨识过程中建立 recipe**

2026-09-09。配套[当前实验主计划](unit_asset_plan_2026-09-09.md)。本文是拟实施协议；已核对已有日志，尚未运行新回放、辨识、真机或 RL。目标是立即用现有数据启动，把新增测量集中在无法解释的差异上。

**1．先建立基线，但无需先完成一轮大规模新采集**

基线包固定四项：原始数据 D0、当前经验曲线和状态机 M0、每条试验的输入/初态定义、输出与评分规则。保存数据和实现哈希；传感器变换、控制器配置和事件提取规则分别记录。先选少量覆盖典型阶段的完整记录调通，再扩大到数据支持的回归集合。M0 的报告是 agent 修改前的起点；数值拟合和通用 agent 等论文对照可以随后运行，不阻挡首轮诊断。

已有汇总共 296 条，其中 `detached_normal=275`、`detached_drag=2`、`detached_lateral=18`、`held=1`。终点脱落是失效边界试验的一种结果，不代表前面的建立和承载都失败。[只读清单](experiments/unit_asset_study/log_inventory_2026-09-09.json)抽查了 3 条详细日志：有 preload/load/hold 等阶段、实际与指令 TCP、实际与指令 wrench、时间和事件；没有关节 q/dq 及完整控制器配置。抽查没有应用成功阈值，不能据此声称已有经过验证的成功片段。`timeout` 也需按原协议解释。

旧表使用了已有数据，因此这些回放属于训练/开发诊断。正式独立验证保留新试验；若另做旧数据交叉验证，经验表和其他拟合组件必须随训练折重建，按完整试验/采集块划分，不能随机切帧。

**2．“当前动作一样”需要明确到仿真的实际输入**

| 模式 | 仿真输入 | 可以评分的预测 | 适用条件 |
| --- | --- | --- | --- |
| Unit 边界驱动 | 实测 unit 相对位移/姿态历史，或另一明确的边界载荷输入 | 未被强制输入的力、运动或接触事件 | 先辨识局部有效响应；输入位移时不能再评分位移 |
| 机器人独立回放 | 实际下发的位姿/力目标、控制模式和时间表，连同初始状态与执行器模型 | 末端运动、wrench、事件 | 需要重建实际控制接口和初始机器人状态 |

第一版优先使用旧数据能支持的模式。若只有 TCP 而安装件可动，不能直接把 TCP 位移当 unit 滑移；可加入相对运动观测，或把资产范围明确为当前安装条件下的有效接触响应。冗余机械臂的 TCP 位姿通常不足以确定原关节构型，不把 IK 得到的一个构型当作已记录的真实 q。

实时版本可把同一条带时间戳的外层命令送给真机和仿真，仿真依靠自己的状态和局部反馈前进。模型在一条试验内固定，agent 在试验间修订。首版也可真实执行一次，然后对多个模型离线重放；严格墙钟同步不是误差辨识的前提。

若 recipe 根据力阈值切换阶段，真机和仿真各自运行 recipe 会产生不同的实际命令序列。这适合评价闭环 recipe，但辨识回放应记录并重放真实下发的目标、模式及切换时刻。控制器仍基于各自状态反馈。评分窗口和中止规则预先定义；人为中止、试验后返回动作与主动释放分别标记。

在力控制下，两边都跟住目标力并不充分证明接触模型正确；还要比较为实现该力产生的位移、饱和及滑移/脱离。反之，在位置作为强制边界输入的测试中，主要检查预测反力和事件。不能强制输入所有实测量，再用被输入的量证明预测正确。

**3．把误差转成可检查的假设，而非只看一个 reward**

每条试验报告阶段、首次有意义的分歧、命令/实测曲线和事件。连续量按传感噪声或任务容差归一化；以试验和阶段汇总，避免长 hold 的大量采样淹没建立与释放误差。时间偏移先用独立校准固定，不逐条自由扭曲时间以消除物理事件误差。

建议保留分项分数：

`J = w_F * E_wrench + w_x * E_motion + w_e * E_event + w_p * E_probability`

只纳入当前测试真正预测的输出；权重与容差在候选比较前固定。事件项包含发生/未发生及可比较时刻，不能只在双方都脱落的样本上算时间误差。到试验上限仍保持属于删失观测，不制造一个脱落时间。概率模型使用重复试验的预测分布和校准指标；一次随机脱落时间不要求逐帧完全相同。每次挂接的随机容量按固定生命周期采样，不根据该条真实结果事后挑 seed。

| 残差现象 | 首先排查/比较的解释 | 有区分力的检查 |
| --- | --- | --- |
| 未接触阶段已有位姿或力偏差 | 坐标、重力补偿、延迟、控制器 | 空载/轻接触短动作；先修接口误差 |
| 同载荷下真实位移更大 | 控制/安装柔顺、unit 有效刚度 | 亚失效加载—卸载，结合 unit 相对运动 |
| 仿真过早认为已建立 | 触发阈值、建立所需运动、观测延迟 | 固定后续检验载荷，改变 seating 距离 |
| 相同当前载荷、不同 seating 历史下结果不同 | 历史状态或未控制的表面/安装变化 | 固定路径，交错改变单个建立条件并重复 |
| 卸载后真实残余位移，仿真完全恢复 | 不可逆滑移、夹具松动或偏置漂移 | 局部位移测量及加载—卸载对照 |
| 各路径容量都偏高 | 容量标定偏差或条件不一致 | 先检验全局容量修正，保留旧承载回归 |

残差形状不能唯一证明某个物理机制。Agent 每轮做以下有记录的操作：

1. 找最早显著分歧及相关阶段，列出 2–3 个替代解释。
2. 固定输入，在仿真中小范围改变相关参数或替换一个候选机制，观察误差变化；有限扰动不要求状态切换可微。
3. 用现有多条数据筛选解释。若它们给出几乎一样的预测，保留不确定性；如该差异影响后续任务，再选预测分歧明显且实际可执行的短探测动作。
4. 真正执行的探测成为新开发数据，各对照方法共享。每轮优先只改变少量参数或一个有证据支持的机制。
5. 候选在全部固定回归和开发验证上重算，检查是否破坏原本正确的承载/释放响应。满足预定规则才接受，不接触最终保留测试。

Agent 可以直接提出参数，也可调用数值拟合器。作为常规参数辨识对照，[MuJoCo System Identification Toolbox](https://github.com/google-deepmind/mujoco/blob/main/python/mujoco/sysid/README.md)提供模拟输出与实测输出的残差拟合及有限差分参数敏感性；工具是否适配当前自定义接触实现仍需集成验证，不能把连续参数拟合等同于自动发现混合状态机结构。

**3a．参数本身随机时，辨识条件分布和随机变量的生命周期**

随机参数不会使辨识目标失效，但会把“找到一个能重放全部记录的参数值”改成“预测同条件下真实结果的分布”。区分四种来源：每次挂接间的有效质量差异、接触过程中随时间演变的状态/扰动、传感器噪声，以及数据有限导致的参数认知不确定性。它们不能全部实现为逐帧独立随机数；未记录的表面、安装和磨损差异也不能直接宣称为不可约随机性。

最小生成模型可写为 `z_i ~ p_phi(z | c_i)`，随后由接触模型根据 `z_i`、动作和接触历史生成第 i 次试验的响应。`c_i` 包括实际可观测的表面/安装条件和建立协议；`z_i` 是该次挂接的潜在有效质量；辨识对象是共享的分布参数 phi 与必要的动力学结构。phi 自身的估计区间或后验另存，不能把“phi 估计不准”直接当作每次挂接的物理方差。

当前[经验模型](../../../src/scr_phybot_mjab/microspine/empirical_limit_surface.py)已经采用条件逆 CDF；[接触实现](../../../src/scr_phybot_mjab/microspine/affordance.py)保存强度和加载成功的随机量，在重新建立时抽样。首版优先延续这一思路：随机质量/分位数在一次挂接内保持，容量仍可随载荷方向和有效状态变化，释放后重新建立才重新抽样。跨载荷方向保持相同分位数是现有模型的联合分布假设，不是仅凭各方向边缘失效曲线就能验证的事实。若有证据显示过程中会滑移、重排或退化，再增加状态演化，而非无条件每步重抽强度。

对每条固定输入，候选模型运行一组随机样本得到预测分布；真实记录在这些预测下评分。不根据真实最终结果挑最接近的随机 seed，也不以“多次仿真中有一次接近”作为准确性。允许根据早期已观测信号估计当前挂接状态，但必须把它明确作为另一种条件预测协议，预先固定观测窗口，只评价未用于估计的后续结果。

评分建议：

- 完整观测的连续量/特征：CRPS 或有明确观测模型的预测负对数似然；同时看区间覆盖率和宽度。
- 建立/保持/释放二值事件：预测概率的 Brier score 或 log loss，连同分条件校准结果。一次真实试验也可获得概率分数，可靠校准结论需足够的独立记录。
- 阶梯失效：若阈值位于 `(L, U]`，该记录的概率为 `CDF(U)-CDF(L)`；到上限 L 仍保持则贡献 `1-CDF(L)`。此形式要求同一给定路径下可用阈值表述、检测模型及删失机制符合协议；一般动态失效改用对应事件/生存模型，不强套静态阈值。
- 时间过程：除逐时刻的区间外，还检查滑移、释放时刻、残余位移等路径特征，避免只拟合边缘分布而漏掉时间依赖。

概率评分应同时约束校准与集中程度，不能无限增大方差来包住所有数据。[概率预测的校准与 sharpness](https://sites.stat.washington.edu/raftery/Research/PDF/Gneiting2007jrssb.pdf)给出了相关评估框架。混合状态机如采用 Monte Carlo 预测，可直接使用样本型评分，不要求每个模型都有解析似然。

实际搜索先沿用旧经验 CDF，只放开少数有证据支持的分布自由度；不预设所有随机量都服从高斯分布，也不独立随机化本应相关的参数。Agent 判断误差来自条件均值、散布、尾部还是历史关系，再选择改分布、加可观测条件或修改状态机制。模型候选之间使用同一套随机采样约定来降低比较噪声，最终评估另用未用于选择模型的样本；增加仿真 seed 不能增加真实证据。

实验先按旧数据中相同的实测条件分组，核对重复和采集块；296 条总记录不等于某个条件有 296 次独立重复。针对关键混淆可比较：同一次挂接内的有界加载—卸载循环、重新挂接后的重复、只改变 seating 的交错试验。记录区域与磨损顺序，同挂接的帧和循环按相关数据处理。若某条件只有少数重复，先保留宽的估计不确定性，不能宣称已确定极端失效尾部。

Recipe 按多次随机 rollout 的任务成功概率、滑移及载荷裕量筛选，可靠性目标预先设定，真实验证另计；不把某个幸运样本的轨迹直接称为可靠 recipe。冻结资产包括分布、条件关系、相关性、随机量更新/复位规则及估计不确定性。后续 RL 从冻结分布采样，actor 只用真实可得的力/运动历史，隐藏抽样值不进入 actor。

相关先例：[BayesSim](https://arxiv.org/abs/1906.01728)推断仿真参数后验并用于 domain randomization，主要说明参数认知不确定性的处理；[STReSSD](https://proceedings.mlr.press/v155/matl21a.html)还辨识物理随机过程的噪声模型参数。二者不能混为“真实参数每次都随机变化”的同一个主张，本项目也无需为此新增重型推断框架。

**4．物理预测和动作成功有两套验收**

| 真机任务结果 | 仿真任务结果 | 下一步判断 |
| --- | --- | --- |
| 失败 | 失败 | 比较过程、载荷和事件；若一致，模型可能正确，改 recipe |
| 成功 | 失败 | 可能过于保守；检查状态、控制与不确定性 |
| 失败 | 成功 | 可能过于乐观；优先定位最早分歧 |
| 成功 | 成功 | 继续比较力、运动和时刻，仅二值成功不足以证明模型正确 |

试验若本来就是拉到失效，unit 脱落不等于实验执行失败。另一方面，准确预测一条错误 recipe 会失败，并不能作为整段任务 motion 的验收。

**5．Recipe 从协议模板和片段开始，不等待全部辨识结束**

初始模板 R0 从既有试验程序与日志提取：

`接近 → 预压 → rake seating → 小载荷验证 → 任务承载 → 卸载 → 退出`

Agent 提出或调整的是阶段参数、条件和必要的阶段变化。例如目标预压力、seating 距离/速度、等待时间、加载路径、卸载后剩余载荷、反向退出距离和阶段时限。数值取自已观测范围；尚无证据的退出方式标为候选。完整 dense motion 由编译器生成，不要求 LLM 逐帧猜位置。

所有原始记录保存，派生三类索引：

| 索引 | 内容 | 用途 |
| --- | --- | --- |
| 阶段候选 | 原日志片段、入口/出口位姿和载荷、前序接触历史、阶段判据 | 建立/保持/释放的候选参数与边界条件 |
| 失败证据 | 失败阶段、前驱状态、实测结果、模型版本和预测误差 | 辨识、避免失败的约束及下一次探测 |
| 完整 recipe | 阶段程序、参数范围、引用片段、连续仿真/真实验证记录 | 编译训练参考，保留验证级别 |

阶段成功判据先确定，并同时看实际载荷和相对运动。例如保持阶段需要达到共同检验载荷并维持规定时长/位移范围；机器人仍在压墙但从未承担拉离要求，不算已证明挂接。标签 `hold` 或 `reached` 本身不能替代这些判据。

一条“建立完成、承载完成、主动释放失败”的记录，可提供前两段候选；最后一段用于诊断和退出策略修正。不能把失败轨迹整体丢弃，也不能把失效后的无载返回标成主动释放成功。如果初期连低载建立都无法稳定完成，先缩短探测动作、检查方向/安装/接口，再查建立机制；没有有效片段时不能凭空生成已验证参考。

拼接片段前检查入口/出口状态兼容：位姿、速度、载荷、接触历史和内部状态分布。不得在片段边界无条件 reset 接触或重新抽取容量，借此绕开历史依赖。完整序列从合法初态连续仿真；存在多个合理模型时，先在其范围内检查候选，而非只挑某个乐观版本。

模型每次更新后，重新检查依赖它的候选 recipe。真实成功记录不会因为新模型不承认而删除，这种矛盾应进入模型诊断。验证级别分别标为日志候选、仿真可行、真实阶段验证、真实完整验证；“仿真可行”不写成“真实可靠”。

**6．编译参考与冻结**

编译器输入是参数化 recipe 和目标，输出是时间/阶段参考、TCP 位姿或速度、相应自由度上的力目标；按机器人需要再经过 IK 和时间参数化。实测 wrench 可作为预期响应或容差，不把所有受约束方向的力和位置同时设为冲突的硬目标。参考跟踪时的阶段信号必须能由真机观测或预设时序实现，不能依赖仿真隐藏接触标签。

辨识过程中可以持续生成、筛选和归档参考候选，不必训练最终 policy。冻结前至少要通过本文所需完整接触周期的开发验证，尤其补上旧失效试验未证明的主动卸载/释放。模型达到预测验收、recipe 达到任务验收后，分别保存版本，再一起组成资产。

最少的 recipe 记录字段为：`recipe_id, phase_program, parameters, support, source_trial_segments, entry_exit_conditions, validation_status, validation_trials, last_checked_model_version, compiler_version`。这些是记录约定，并不表示当前工程已有完整编译器。

冻结后，由固定 recipe 编译器和固定模型为范围内的新目标生成参考，再进行常规仿真 RL；不要求每条新 reference 先在真机录一遍，也不再调用 agent 修接触模型。RL 两个模型组使用同一参考集，保证模型比较公平。真实终评不反馈为新的训练数据；如果反馈后修订，需新的独立终评。

**最先落地的三个交付物**

1. M0 残差报告：明确输入、输出、控制假设，列出阶段误差和当前无法辨识的量。
2. 旧日志阶段索引：按固定判据提取候选有效片段与失败约束，保留来源和前序接触历史。
3. 下一轮动作队列：分别标明“区分模型假设的 probe”和“完成任务的 recipe”，附预期观测、判据及对应模型版本。只补能解决现有缺口的真实试验。

这三个交付物属于下一步实现工作；目前完成的是协议与只读日志清单。
