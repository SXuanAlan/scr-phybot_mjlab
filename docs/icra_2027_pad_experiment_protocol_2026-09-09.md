**整 pad 实验协议：从单 unit 外推验证到机械臂接触技能**

2026-09-09。接续[机械臂 real2sim2real 方案](icra_2027_real2sim2real_2026-09-08.md)。本文件是拟议实验设计，尚未采集新数据、训练策略或运行硬件。实验次数是排程建议，不是统计功效保证。

**当前执行入口：**[单 unit 模型资产方案](icra_2027_unit_asset_plan_2026-09-09.md)。当前 bare minimum 不要求整 pad；下文为历史设计，次数不与新方案累加。

同日补充：[Agent 接触模型辨识方案](icra_2027_agentic_contact_identification_2026-09-09.md)扩展到状态转移、柔顺和缺失机制的诊断。若采用该范围，下文 E2 的 24 条仅作为筛查起点；新增辨识探针和独立动态测试须另计，不包含在原总次数中。

**主线：单 unit 数据提供先验；整 pad 实验检验并在必要时修正外推；冻结后的仿真支持参考生成与控制，最后用真实接触技能验证。** 下一轮优先测最终部署的 pad、安装结构和加载路径。重新铺满一张更密的单 unit 曲线，对这条证据链的帮助较小。

当前按单机械臂、固定粗糙墙面、可获得六维力/力矩测量设计。实物 pad 的 unit 数量、布局、腕部连接和控制接口尚待确认；不直接采用仿真 CAD 的数量或安装方式作为实物事实。载荷数值、速度、位移阈值和行程须由先导试验确定，本文没有给出可直接下发硬件的命令。

现有[原始汇总](../data/microspine/raw/20260905-110314/results.csv)包含 296 条有效试验；部分为前序批次合并。当前经验表主要使用失效事件的指令法向力。详细日志已经包含 TCP/world 六维 wrench、指令和阶段时间戳，因此先重提失效前数据，无需仅为补上力矩记录而重测单 unit。事件触发时的实测力可能已经下降，不能直接当成最大承载能力。

[经验模型](../src/scr_phybot_mjab/microspine/empirical_limit_surface.py)明确将 unit 独立性、跨方向分位秩保持及首个 unit 失效触发 pad 释放作为假设；[wrench 分配](../src/scr_phybot_mjab/microspine/wrench.py)同时已有等刚度和可选加权实现。实现存在不等于实物已验证。现有 runtime 表在单 unit 回顾性验证后使用全部单 unit 数据重拟合，不能再以这些样本作独立测试。

**先导：对齐测量与实际可施加的载荷**

建议先做 8–12 次整 pad 重新挂接，全部计入开发，不进入最终测试。确定以下事项后，冻结正式协议：

1. 确认实际 unit 布局、安装参考点、表面区域和 pad 姿态。完成力传感器偏置、工具重力和坐标变换检查；运动较快时还需考虑工具惯性项。
2. 统一 pad 中心 C 的 wrench 定义。若传感器原点为 S，先统一坐标轴，再使用 `F_C = R_CS F_S`、`M_C = R_CS M_S + (p_S - p_C) × F_C`。明确记录的是施加载荷还是反作用力，并统一符号。
3. 自由空间短动作先检查执行接口响应；再测接触，避免把控制器延迟或安装件柔顺误识别为 microspine 参数。
4. 选择可重复的预压、沿抓附方向拖动距离、建立等待、载荷步长和保持时间。沿用旧试验每级约 3 s 的节奏有利于比较，但需实测能稳定跟踪；不能把单 unit 的 10 N 预压乘以 unit 数，就认为每个 unit 均受到 10 N。
5. 固定正常滑移、首次明显滑移、完全脱离和释放完成的测量定义。阈值依据传感噪声与任务容许误差确定，测试后不按算法修改。

**力矩实验取决于连接方式。** 刚接或可承受力矩的连接，可以检查不同剥离力矩。自由球铰在固定作用点下的中心力矩主要受 `M_C = r × F` 约束，不能独立任意指定六维 wrench。要做“同一合力、不同力矩”，必须确有可传递的外加力矩或不同的实际载荷作用线。没有该条件时，P5/P6 改为可实现的加载方向/对齐变化，论文只声称相应可达载荷路径的验证。不要为台架临时改成刚接、部署时改回球铰，却沿用未验证的参数。

若安装件可转动或明显柔顺，仅靠腕部位移不能区分 pad 相对墙面的滑移与关节变形。优先增加可见标记与同步视频，测 pad—墙面相对位姿；有现成更精确传感器时使用它。

**E1：现在最应补测的整 pad 承载实验**

固定一种标准建立协议。每次重新挂接后先到目标切向载荷，再逐级改变法向载荷，直到脱离或达到预设实验上限。建议六条路径，每条 16 次重新挂接，共 96 次；其中每条 8 次开发、8 次保留测试。压缩版每条 12 次，6 次开发、6 次测试，共 72 次。

定义 S 为抓附方向切向载荷，L 为侧向载荷，Fn 为法向载荷；Fn 的正方向表示拉离表面。`S_lo`、`S_hi`、`L_ref` 和偏心量在先导后填入，所有路径记录实际完整 wrench。

| 路径 | 保持/改变的条件 | 主要检验什么 |
| --- | --- | --- |
| P1 | 较低正向切向载荷 S_lo，L=0，名义作用线；扫描 Fn | 整 pad 的基本承载与单 unit 外推 |
| P2 | 较高正向切向载荷 S_hi，L=0，同一作用线；扫描 Fn | 抓附方向载荷对法向承载的影响 |
| P3 | S_lo、+L_ref，同一作用线；扫描 Fn | 侧向载荷耦合 |
| P4 | S_lo、−L_ref，同一作用线；扫描 Fn | 当前侧向镜像假设是否足够 |
| P5 | 与 P1 相同合力路径，增加一个方向的剥离力矩/偏心 | 力矩或作用线效应；需硬件支持 |
| P6 | 与 P1 相同合力路径，反向剥离力矩/偏心 | 相反剥离方向；需硬件支持 |

P5/P6 不可独立施加时，可用较弱反向抓附载荷、或正负初始倾角等可达条件替代；正式采集前选定，不能再把它解释为独立力矩消融。六条切片不构成完整六维边界，当前目标是覆盖最终任务实际访问的载荷范围。

每次试验的有效输出包括：

- 建立是否成功；失败发生在建立、切向加载、侧向加载还是法向扫描阶段。扫描前失败不能被丢弃或强行填成一个法向失效阈值。
- 最后稳定保持阶段的实际 wrench 分布、下一失败级的命令及失效前实测轨迹。保留指令量与实测量，分开使用。
- 首次明显滑移/部分分离，以及最终整 pad 脱离的时刻与载荷。全局力下降不能证明具体某个 unit 失效；无 unit 级观测时，只评价 pad 级事件。
- pad 相对墙面的平移/转角、加载速度、保持时长、试件/表面区域、重新挂接次数与磨损记录。

阶梯加载只能给出“最后稳定级—下一失败级”的阈值区间；到上限仍保持属于右删失。指令力可在同一协议下比较阈值，实测 wrench 用于物理辨识。若把旧 unit 表转换为实测力版本，须从详细日志提取稳定段和失效前窗口、验证力跟踪并版本化；新旧模型比较采用一致的测量定义，不能把指令容量与接触实测力混为一谈。

开发与测试按表面区域分组隔离；记录 pad 覆盖范围，不能只看 TCP 中心。组内随机交错各加载路径，记录采集顺序与 unit 更换，减小表面差异和磨损混杂。允许重新使用区域，但需记录并按区域/采集块处理相关性；一段时间序列或连续十个力级不等于十次独立试验。只有一种面板时，结论限定为该面板上未参与拟合的区域，不声称跨材料泛化。

**E1 比较哪些模型**

| 模型 | 允许使用的整 pad 开发数据 | 比较意义 |
| --- | --- | --- |
| U：现有单 unit → pad 合成 | 不拟合整 pad 参数 | 检查已有外推本身是否成立 |
| S：U + 一个全局承载缩放 | 与下一组相同 | 强简单基线：是否仅校正总体大小即可 |
| W：U + 少量受数据支持的修正 | 与 S 相同 | 是否需要载荷方向、力矩或建立相关修正 |
| W 去掉独立力矩修正，条件性增加 | 与 W 相同 | 只有独立力矩确实可变化时才解释力矩作用 |

先比较 U/S，再依据开发集残差选择 W；不预设一定需要更复杂模型。W 优先限制为 2–4 个可辨识的有效参数或少量已有模型配置。单靠总 wrench 与脱离时刻，通常不能唯一分解 unit 强度相关性、实际挂接比例、每个 unit 刚度和逐 unit 载荷重分配；这些机制不能同时宣称被辨识出来。

主要报告留出试验的边界区间误差、规定载荷下的保持/失败预测；概率模型再报告 Brier score、预测区间覆盖率及宽度。错误接受率须同时报告接受率/完成率，否则“拒绝所有任务”也会显得可靠。按加载路径展示样本与不确定性，不仅给一张光滑包络图。每条测试仅 6–8 次时，不能验证 99% 保持可靠性。

U 与 W 的差异包含新增数据的作用；S 与 W 在相同开发数据下的差异才检验复杂修正是否必要。若强调“单 unit 先验提升数据效率”，再加入相同整 pad 数据预算的直接 pad 拟合基线。若强调“组合模型适用于不同 unit 数量/布局”，必须增加第二种实物布局的冻结模型测试；本轮只有最终一种 pad 时不作该 claim。

**E2：补建立与释放，连接失效曲线和完整动作**

建议 2 种建立方式 × 2 种释放方式 × 6 次重新挂接 = 24 条短序列，全部作为开发数据。最终技能测试另取新试验。

| 因素 | 两个水平 | 固定不变 |
| --- | --- | --- |
| 建立 | 标准拖动距离；较短但合理的拖动距离 | 预压、姿态、速度、等待时间 |
| 释放 | 规定卸载后直接退离；同样卸载后短距离反向切向运动再退离 | 卸载要求、退出行程范围和允许时长 |

每条执行：接近 → 建立 → 规定载荷保持约 3 s → 卸载 → 释放。负载保持不能靠额外向墙压紧来替代 microspine 抓附；测试要求应包括任务所需的拉离分量。失败也保留，释放指标同时报告总试验结果和“已成功建立”条件下的结果。

记录建立成功率、建立所需时间/位移、保持期间滑移、卸载后残余载荷、释放成功率和释放时间。这 24 条用于检验任务相关的阶段差异与简化状态转换；不足以同时识别复杂疲劳、速率和时间失效模型。不同等待时长、重复寿命和多种预压曲线先不全面展开，除非残差或任务明确要求。

同输入 real/sim 比较使用相同的外层位姿/力目标序列和对应的低层控制接口。只在开始对齐状态，仿真随后自由演化，各自的本地反馈正常工作；不可逐帧覆盖成真实状态，或将实测接触力强制施加给仿真后称为接触预测。比较滑移、wrench 和阶段事件的分布，随机挂接不要求逐次毫秒级复现。

**E3：agent 是否有增量，先用离线实验回答**

固定候选模型、拟合工具、参数范围和开发数据，比较：数值拟合/模型选择流程；能访问相同物理信息和工具的通用 Astra coding agent；带明确接触误差诊断与反馈决策的拟议方法。记录独立预测误差、查询试验数、仿真调用数、总耗时、模型费用/配额使用及人工修改次数。订阅或 API 是实现与成本记录项，不是方法优劣的判据。

一个可执行的回顾性设置是：从 E1 的 48 条开发数据中，每条路径先给 2 条，共 12 条；其余 36 条作为可查询数据池，比较额外查询 0/6/18/36 条后的预测。相同初始数据、相同预算、相同最终测试集。每种随机流程可重复 5 次，测试集仅由独立评估程序访问，不能用于 agent 选模型。算法重复不增加真实独立样本量。

这只能证明有限数据池中的查询/诊断效果。不能将它写成已经在线自主采集，或已经实际省下同样数量的硬件试验。若主动选择是核心贡献，还需加入合理的不确定性/信息量选点基线；若要声称在线采集效率，需另做实际闭环采集验证。

参考生成再用 6–8 个预先规定的任务实例比较：共同初始几何参考；等预算数值参数搜索；接触反馈指导的 agent 修正。模型在此之前冻结，允许调整接近/拖动/卸载轨迹与阶段时长，不允许降低必需载荷、缩短必需保持时间或改动任务终点。按预定规则在开发集选择参考，所有失败候选和计算成本计入预算。

若普通数值搜索同样好，就把它作为强基线；若它影响论文的核心结论，需要进入真机比较。不能仅凭完整系统成功，就断言 agent 优于数值工具。

**E4：主 demo 与完整任务比较**

建议任务定为：**未挂接开始 → A 点建立 → 承受规定载荷 → 卸载释放 → 移到 B → 重新建立并承载。** 可将其准确描述为攀爬单肢的接触转换技能。机械臂底座固定，这个演示本身不等于机器人自主攀爬。

统一规定 A/B 目标、最小负载和方向、两次保持时长（建议各 3 s）、位姿容差、总时限、最大重试次数、滑移阈值及最终结束状态。所有方法都要满足相同任务要求；中途人工复位算本次失败。若允许自主重试，各组使用相同预算，并同时报告首次成功率与允许重试后的成功率。

| 组别 | 仿真/参考 | 真机执行 | 回答的问题 |
| --- | --- | --- | --- |
| A | 旧单 unit 合成模型 U + 合理参考 R0 | Tracking RL | 从现有成果直接出发的基线 |
| B | 整 pad 开发数据校准后的模型 + 相同 R0 | 同配方 Tracking RL | A→B：整 pad 校准的作用 |
| C | 与 B 相同模型 + 经物理检查修正的 R1 | 同配方 Tracking RL | B→C：参考修正的作用 |
| D | 与 C 相同参考、阶段信息和可用反馈 | 调好的代码/阻抗/力反馈控制器 | C↔D：是否确实需要 RL |

A/B 都允许合理的通用调参，训练步数、网络、参考数量和除目标接触模型外的随机化保持一致。U 若在先导中明显无法描述最基本行为，应透明报告；同时用 E1 的单参数校准基线判断是否简单校准就能解决，不能把 U 设成唯一模型对手。E1 中数值校准已经同样好时，也不把 A→B 的收益全归因于 agent。

D 使用同样部署可得的观测，包含阶段切换、力反馈和合理的恢复逻辑，可采用 Astra 编写且经过开发集调试的程序。它不应只是关节位置开环播放。已有 [Code as Policies](https://code-as-policies.github.io/) 包含反馈控制与阻抗行为，因此“大模型慢”不足以解释为什么需要 RL；需要检验接触不确定性和状态偏差下的实际差异。此处 D 是本项目实现的代码控制基线，不自动等于完整复现原论文。

Actor 仅使用真机可获得的状态、参考与力/力矩等观测。仿真挂接真值和 unit 隐变量可供 critic/评估，不进入可部署 actor。仿真动作必须映射到真实支持的接口，不能使用真机不存在的直接外力注入。

建议 A/B/C 各 3 个训练 seed，共 9 次训练；四种方法 × 两种条件 × 每格 15 条完整试验 = 120 条真机任务。RL 每个 seed 在每个条件执行 5 条，D 每个条件 15 条重新开始的试验。报告各 seed，而不把 15 次执行说成 15 个独立训练结果。

两种条件为：名义初始条件；一个预先确定的挑战条件。优先选择适度初始对齐误差；实际安装支持时也可改为偏心加载。首版只改变一个因素。最终目标区域不参与开发，组间按区域与采集块随机交错，记录表面复用和磨损。

主指标是整段任务完成率。另报告各阶段失败、意外脱离、最大滑移、实际承载、释放失败和总时间；给出原始计数、各 seed 结果和与分组设计相符的不确定性。位姿轨迹画得相似、只完成 A 点挂接或让 pad 一直压住墙，都不足以构成整段任务成功。

2. 模型图：六条路径的真实样本、旧外推、简单校准和最终模型预测；再选一条同输入短序列展示真实与仿真的阶段差异。离线回放明确标记，不称实时数字孪生。
3. 方法图：相同任务与约束下的代表性失败/成功及相应残差诊断。由已有正式试验选取，避免额外布置容易失败的基线或把不同难度的表面当成方法差异。

若已有粗糙试件与合适夹具，可将功能演示升级为“单面挂附 → 小距离提起/转移 → 小角度调整 → 支承放置 → 卸载释放”。这比台架承载更容易呈现操作价值，但涉及物体质量、惯性与夹具验证；只在现成条件支持时做，不能为赶工作量另开硬件项目。人形仿真可展示同一接触模型的使用范围，但不代替真实整 pad 与机械臂实验。

**如何由结果决定 contribution**

整 pad 数据的作用是使接触模型得到独立验证，并证明这种预测对参考/控制有用。“又测了一张失效曲线”本身不足以成为新的建模方法；spine array 的随机承载与加载方向关系已有[相关研究](https://journals.sagepub.com/doi/10.1177/0278364918778350)。候选贡献应落在本项目可验证的接触误差诊断、少数据校准及其对技能迁移的作用。

如果 U 已预测准确，保留其验证价值，减少不必要修正；如果 S 已足够，不硬加复杂 pad 模型。如果通用 agent/数值流程同样好，将 agent 定位为工具；如果 D 与 C 同样好，弱化或移除 RL 必要性的主张。完整的研究故事由对照结果决定，不要求每个技术名词都成为一项贡献。
